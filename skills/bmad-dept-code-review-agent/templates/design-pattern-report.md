## Effort-vs-block guidance

Not every design-pattern violation should block a merge. Use this rubric
when deciding whether a violation is a blocking comment or a
follow-up-ticket comment:

| Effort | Typical treatment |
|---|---|
| `S` (< 30 min, local to the diff) | Ask for the fix in this PR — cheap enough that deferring it just creates review debt. |
| `M` (< half day, may touch adjacent files) | Reviewer judgment — fix now if the PR is otherwise small, defer via `.bmad/decisions.yaml` (`deferred`) if the PR is already large. |
| `L` / `XL` (multi-file refactor, architectural) | Do not block this PR on it. File as a follow-up and record a `deferred` decision with a `next-review` date; consider escalating to the Architecture agent if the pattern recurs across PRs. |
