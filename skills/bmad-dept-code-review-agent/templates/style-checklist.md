## Notes on precedence

When a custom `--style-guide` rule conflicts with a built-in per-stack
convention (e.g. the custom guide mandates 2-space indent where the
stack default is 4), the **custom guide wins** — it represents the
team's explicit override. Flag the conflict as an INFO-severity note
rather than silently picking one, so the team notices the divergence.

## Footer

_Style rules are checked only against lines the diff touches — this is

into CI directly; this artifact exists to catch what the linter would
also catch, but framed as a pre-merge review comment rather than a build
failure._
