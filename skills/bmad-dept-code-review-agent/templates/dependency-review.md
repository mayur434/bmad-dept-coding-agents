## How to read this file

One entry per dependency change (added / removed / version-bumped) found
in the diff's manifest files. Each entry carries a license check, a
known-vulnerability check (CVE, when obviously flaggable from the version
delta), a transitive-impact note, and a recommendation.

## Risk level reference

| Risk level | Meaning | Maps to |
|---|---|---|
| `blocking` | Known active CVE with no available patch, or a license change incompatible with the project's license policy. | `CRITICAL` |
| `high` | Major version jump with unreviewed breaking-change surface, or a CVE this bump doesn't fully address. | `HIGH` |
| `moderate` | Minor version jump, or an added dependency without an obvious red flag but worth a second look. | `MEDIUM` |
| `low` | Patch-level bump, or a removal with no remaining references. | `LOW` |
| `informational` | No actionable risk — noted for completeness. | `INFO` |

## Footer

_This is a pre-merge risk read, not a full software-composition-analysis
(SCA) scan — for exhaustive vulnerability coverage across the entire
dependency tree, wire a dedicated SCA tool (Snyk, Dependabot, OWASP
Dependency-Check) into CI. This artifact catches what's visible and
obviously flaggable from the version delta in the diff._

_See `REVIEW-COMMENTS.md` for these same findings rendered as inline PR
comments, and hand flagged entries to the Release agent
("block the deploy plan on unresolved dependency flags") if any are
`blocking` or `high` risk._
